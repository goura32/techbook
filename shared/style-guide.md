# Style Guide

## 文体

- です・ます調を基本とする
- 断定が必要な箇所では、曖昧な表現を避けて簡潔に書く
- 1文は長くなりすぎないようにし、主語と述語の対応を明確にする

## 文章構成

- 章の冒頭で、読者が得られることを短く示す
- 節では「背景 -> 手順/説明 -> 結果 -> 補足」の順を基本とする
- コード例の前後では、何を示すコードかを明示する
- 長い説明は箇条書きや表に分け、視認性を保つ

## 見出し

- 章は読者の学習順に沿って並べる
- 見出し名は短く具体的にする
- 同じ粒度の見出しでは命名規則をそろえる

## コード例

- 最小限で再現可能な例を優先する
- サンプルコードには、読者が読み飛ばしても意図が分かる短い説明を添える
- 例示用コードと本番運用向けコードは、前提条件の違いを明記する
- OS やツールのバージョン依存がある場合は注記する

## 図表

- 図表の目的を本文中で明示する
- 図だけで理解させようとせず、本文でも要点を補う
- スクリーンショットは必要性が高い場合に限定する

## 表記

- 数字と単位の間は半角スペースを入れる
- コマンド、ファイル名、識別子は `` `code` `` で囲む
- 書名、章名、節名の表記ルールは書籍全体で統一する
- 同じ概念に複数の日本語訳を混在させない

## 禁止事項

- 他書ですでに詳説している内容を、背景説明から重複して書かない
- 根拠のない「簡単」「直感的」といった評価語を多用しない
- バージョンや実行環境の前提を伏せたままコードを提示しない
