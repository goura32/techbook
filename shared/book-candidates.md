# Book Candidates

このファイルでは、将来的に執筆する候補書籍を管理します。
各候補は、KDP で単独の書籍として成立するか、既存候補と役割が重複しないか、実務で必要な情報をどこまで扱うかを基準に評価します。

## シリーズ方針

- 共通タイトル部は `技術の輪郭` を採用する
- 各巻ではサブタイトルで対象範囲と実務上の価値を具体化する
- シリーズ全体では「技術の全体像をつかみ、実務で判断できるようにする」ことを共通価値にする

## 初期ラインナップ

- `typescript-practical`: 技術の輪郭 TypeScript
- `python-practical`: 技術の輪郭 Python
- `git-github-practical`: 技術の輪郭 Git & GitHub
- `hermes-agent-practical`: 技術の輪郭 Hermes Agent
- `usb-from-spec`: 技術の輪郭 USB

## 運用ルール

- まだ執筆を開始しない段階でも、候補はここへ記録する
- 候補を採用したら `books/<book-id>/` を作成し、詳細はそちらへ移す
- 似た候補が複数ある場合は、「1冊にまとめる案」と「分冊する案」を併記する
- 他書と共通化できる説明が見えたら、`shared/common-explanations.md` に候補を追記する

## 現時点の優先候補

### 言語系

#### Python

- 候補名: 実務で使い切る Python
  - 仮 book-id: `python-practical`
  - 狙い: 文法入門ではなく、実務で必要な標準ライブラリ、型ヒント、テスト、パッケージ管理、CLI、非同期、データ処理、Web/API 連携までを一冊で整理する
  - 読者: Python 初級者を卒業して、実務で安全に書きたい人
  - 差別化: 「書ける」より「壊れにくく保守しやすい」を中心にする
  - 備考: データ分析専用本にはせず、業務自動化とアプリケーション開発の両方を扱う

- 分冊候補:
  - Python テスト設計
  - Python 型ヒント実践
  - Python 非同期処理
  - Python 標準ライブラリ活用

#### Rust

- 候補名: 実務で育てる Rust
  - 仮 book-id: `rust-practical`
  - 狙い: 所有権の入門で終わらず、エラー設計、トレイト、モジュール設計、非同期、CLI、テスト、FFI、運用時の注意点まで含める
  - 読者: Rust を触ったことはあるが、実務導入へ踏み込めていない人
  - 差別化: コンパイラに通るコードから、長期保守に耐える設計へ進める
  - 備考: Web バックエンド特化ではなく、CLI と基盤ツール開発も重視する

- 分冊候補:
  - Rust で作る CLI
  - Rust 非同期処理実践
  - Rust テストと品質保証
  - Rust FFI とシステム統合

#### TypeScript

- 候補名: 実務 TypeScript 設計
  - 仮 book-id: `typescript-practical`
  - 狙い: 型システムの理解、ランタイムとの境界、フロントエンド/Node.js 双方での設計、テスト、ビルド、パッケージ公開まで扱う
  - 読者: JavaScript 経験者で、TypeScript を本格運用したい人
  - 差別化: 型の書き方ではなく、型を使って設計事故を減らすことに重点を置く
  - 備考: React 専用本にはせず、土台となる言語・設計本にする

- 分冊候補:
  - TypeScript 型システム実践
  - TypeScript で作る Node.js アプリケーション
  - TypeScript フロントエンド設計
  - TypeScript ライブラリ開発

## 4冊目候補メモ

### 優先順位

1. `hermes-agent-practical`
2. `opencode-practical`
3. `openclaw-practical`

### 判断メモ

- `Hermes Agent`
  - シリーズ `技術の輪郭` と相性がよい
  - コーディング、スキル、MCP、メモリ、Cron、メッセージングまで一冊の軸を作りやすい
  - OpenClaw からの移行文脈もあり、比較本としても組み立てやすい
- `OpenCode`
  - コーディングエージェントとして非常に強いが、変化が速く、実装やUI更新に追従する負荷が高い
  - いずれ書く価値は高いが、4冊目より5冊目以降のほうが安定しやすい
- `OpenClaw`
  - 規模と話題性は大きいが、対象範囲が広すぎて 1 冊の設計が難しい
  - セキュリティ、運用、プラグイン、メッセージングなど論点が多く、初期シリーズには重い
