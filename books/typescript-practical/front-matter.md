## はじめに

TypeScript は、JavaScript に型を足すためだけの言語ではありません。実務ではむしろ、外部入力をどこで疑うか、内部で信頼する型をどこに置くか、公開 API をどこまで絞るか、更新に強いツールチェーンをどう保つか、といった判断のほうが長く効きます。本書は、TypeScript をそうした判断を支える言語として捉え直すことを目的にしています。

TypeScript の文法や型テクニックそのものを解説する資料は多くあります。一方で、日々の開発で本当に困るのは、型システムそのものよりも、その型をどこで効かせるかという設計上の問いであることが少なくありません。API レスポンスをそのまま流してよいのか、Node.js とフロントエンドでどこまで原則を共有できるのか、`tsconfig` や CI の基準をどう揃えるのか。こうした問いに対して、章ごとにばらばらではなく、ひとつの視点で答えられる本にしたいと考えました。

本書で繰り返し使う中心的な視点は、`境界で疑い、内部で安定させる` ことです。外部入力はそのまま信じず、境界で検証し、内部モデルへ変換し、必要ならさらに表示向けの形へ整える。この流れは、ランタイムバリデーション、公開 API 設計、Node.js 実行環境、フロントエンドの画面モデル、継続運用のすべてに通じます。

その視点を具体的に追えるようにするため、本書では `TaskHub` という小さな通しサンプルを使います。これは完成品を見せるための題材ではなく、型、境界、変換、公開面、運用の判断がどこで効いてくるかを追うための題材です。各章で少しずつ改善していくので、抽象論だけで終わらず、同じ題材を通して設計の変化を見比べられます。

本書は、TypeScript を「厳密な型を書くための言語」としてではなく、「変化に耐えるコードベースを育てるための言語」として使いたい読者に向けて書かれています。読み終えたときに、型の書き方だけでなく、どこで何を疑い、どこを安定させるべきかという判断軸が手元に残ることを目指しています。

## 本書の読み方

本書は 1章から順に読むと、考え方が最も自然につながるように構成しています。特に 1章から4章は、後半の前提になるため、最初に通して読んでおくと理解しやすくなります。

Node.js 側の関心が強い読者は、1章から6章を主軸にし、7章を UI 境界と画面モデルの参考として読むとつながりやすくなります。フロントエンド側の関心が強い読者は、1章から5章と7章を主軸にし、6章を実行環境と内部モデル整理の参考として読むのがおすすめです。Node.js とフロントエンドの両方を扱う読者は、1章から11章を順に読むと、本書の狙いが最も一貫して見えてきます。

付録は、本文を補助するために役割を分けています。付録 A は `TaskHub` の構造、付録 B は型と関数の対応、付録 C は代表コード断片の確認に向いています。本文を読み進める中で `TaskHub` 全体を見失いそうになったら、必要な付録へ戻る使い方が自然です。

また、本書は特定フレームワークの詳細や型パズルの技巧を追う本ではありません。細かな文法の網羅より、実務で繰り返し現れる判断軸を優先しています。そのため、気になる章だけを拾い読みするよりも、まずは章の導入と結論を追いながら、自分の現場に引き寄せて読むと効果が出やすくなります。
