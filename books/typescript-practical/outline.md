# Outline

## 書籍の目的

- TypeScript を単なる型付き JavaScript としてではなく、実務で設計事故を減らすための言語として理解できるようにする
- 型システム、ランタイム境界、ビルド、Node.js とフロントエンドの接続点をひとつの視点で整理する

## 仮タイトル

- 技術の輪郭 TypeScript
- サブタイトル案: 型システム、設計、ツールチェーン、運用を横断して理解する

## 通しサンプル

- 題材名: `TaskHub`
- 概要:
  - `shared`: 共通型とユーティリティを持つパッケージ
  - `api-client`: 外部 API と通信し、レスポンスを内部モデルへ変換する層
  - `cli`: タスク一覧や同期を行う Node.js CLI
  - `web`: タスクを表示・編集するフロントエンド
- ねらい:
  - 型定義を共有しつつ、境界でそのまま流用しない例を作る
  - Node.js とフロントエンドの両方で同じ設計原則を追えるようにする
  - 章ごとに「いま何を改善したか」が見えるようにする

- 3章: ジェネリクスやユーティリティ型を設計にどう効かせるかを扱う
- 4章: 外部入力に対して型だけでは安全にならないことを説明する
- 5章: ライブラリや社内モジュールの公開面をどう設計するかを扱う
- 6章: CLI、サーバー、スクリプトでの活用を扱う
- 7章: UI 層と状態管理、API クライアント境界の設計を扱う
- 8章: テスト戦略、ソースマップ、ビルド速度と品質のバランスを扱う
- 9章: `tsconfig`、Lint、Formatter、CI の連携を扱う
- 10章: TypeScript 6.0 系と 7.0 native preview を踏まえ、速度改善、互換性、移行判断を扱う
- 11章: バージョン更新、破壊的変更、チーム運用の勘所を扱う

## 他書との役割分担メモ

- `Python` とは「実務基盤」という観点が重なるが、本書は型による設計と JavaScript 生態系との境界に集中する
- `Git & GitHub` にあるレビューや履歴管理の詳細には踏み込みすぎない
- `Hermes Agent` で使う設定管理や CLI 基本論の一般部分は共通説明へ寄せる
- TypeScript の新機能紹介だけに寄らず、移行判断とツール互換性の説明を重視する
