# 9章 リリース、タグ、バージョニング

変更を流す運用が整ってきたら、次に必要なのは「どの状態を公開単位として扱うか」を明確にすることです。ここで混ざりやすいのが、タグ、リリース、バージョンです。これらは関連していますが、同じものではありません。

タグは、特定のコミットに印を付けるものです。リリースは、その公開単位に説明や資産を持たせるものです。バージョンは、利用者に対する互換性の約束です。この 3 つを分けて考えると、運用がかなり整理しやすくなります。

`BeaconBoard` のようなプロダクトでも、main に入った変更をそのまま「公開」とは限りません。ある程度まとまった機能群や、運用上意味のある区切りでタグを打ち、release notes を作るほうが後から追いやすくなります。逆に、タグだけを打って説明がないと、何が変わったのかが分かりづらくなります。

セマンティックバージョニングも、魔法のルールではありません。互換性の約束を明確にするための道具ですが、チームやプロダクトの現実に合わせて使う必要があります。特に社内向けツールでは、バージョン番号の見た目よりも、どの変更が破壊的かを運用上どう共有するかのほうが重要になることがあります。

hotfix をどう流すかも、リリース運用の一部です。release branch を切るのか、main から直接タグを切るのか、fix を `cherry-pick` で運ぶのか。ここでも大切なのは、手順の正しさより、後で誰が履歴を見ても追える形かどうかです。

この章で大事なのは、公開単位を曖昧にしないことです。タグ、リリース、バージョンにはそれぞれ役割があり、そこを分けるだけで障害調査や問い合わせ対応もかなり楽になります。次の章では、誤操作や不整合が実際に起きたとき、どう復旧するかを具体的に見ていきます。
