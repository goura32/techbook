# Code Samples

## 目的

- 本文と付録で、どこまでコマンドや設定を載せるかの基準を固定する
- 読者が追える密度を保ちつつ、紙面で重くなりすぎることを避ける

## 方針

- 本文では、判断に直接効く短いコマンド断片と設定断片を優先する
- 連続した運用フローや事故復旧のまとまりは付録 C で補う
- `BeaconBoard` の全体像は付録 A、主要操作と GitHub 機能の対応は付録 B で確認できるようにする
- 危険な操作は、必ず `どこで使うか` と `どこでは使わないか` をセットで示す

## 章ごとの重点

- 1章から4章:
  - コミット、PR、レビューの短い例を優先する
- 5章:
  - `rebase` `cherry-pick` `revert` 周辺を短い履歴例で示す
- 6章と7章:
  - rulesets と merge queue は設定概念を優先し、UI の細部へ寄りすぎない
- 8章と9章:
  - Issue、Projects、releases はワークフロー中心に扱う
- 10章:
  - 復旧系コマンドは、危険性と安全域が分かる形で載せる
- 11章:
  - テンプレート、チェックリスト、運用ルール例を中心にする
