# Appendix B. 主要操作と機能の対応

## この付録の役割

この付録は、本文で登場した主要な Git 操作と GitHub 機能を、変更の流れに沿って見直すためのものです。コマンドと画面機能を別々に覚えるのではなく、「どの局面で何を使うか」という対応で整理します。

## 変更の流れで見る

`BeaconBoard` の日常開発は、大きく次の流れで進みます。

1. ローカルでコミットする
2. feature branch を push する
3. Pull Request を作る
4. レビューを受ける
5. 保護設定と CI を通す
6. 必要なら merge queue に乗る
7. main へマージされる

## 主要操作

### コミットを作る

- Git: `commit`
- 主な登場章: 2章
- 役割: 変更単位を切る

### 履歴を整える

- Git: `rebase`
- 主な登場章: 3章, 5章
- 役割: 公開前の履歴整理、main への追従

### Pull Request を作る

- GitHub: Pull Request
- 主な登場章: 4章
- 役割: レビュー単位を作る

### 保護設定を入れる

- GitHub: rulesets / protected branches
- 主な登場章: 6章
- 役割: main を守る

### 直列マージする

- GitHub: merge queue
- 主な登場章: 7章
- 役割: CI とマージ順を安定させる

### 部分的に取り込む

- Git: `cherry-pick`
- 主な登場章: 5章, 9章, 10章
- 役割: hotfix や限定的な復旧

### 共有履歴上で打ち消す

- Git: `revert`
- 主な登場章: 10章
- 役割: 共有ブランチの復旧

## 最後に見るべきこと

持ち帰ってほしいのは、コマンドや機能名そのものより、「どの変更をどの局面でどこまで安全に流せるか」という判断です。Git と GitHub を別々の道具としてではなく、ひとつの変更管理の流れとして見ると、使い分けがはっきりします。
