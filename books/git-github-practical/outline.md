# Outline

## 書籍の目的

- Git と GitHub を、コマンド集としてではなく、チーム開発の変更管理システムとして理解できるようにする
- 履歴設計、レビュー、ブランチ戦略、トラブル対応まで含めて、実務で破綻しにくい運用を示す

## 仮タイトル

- 技術の輪郭 Git & GitHub
- サブタイトル案: レビュー、保護設定、マージ戦略、事故復旧の実務

## 章構成案

1. Git と GitHub をどう使い分けるか
2. コミット、履歴、差分の基本設計
3. ブランチ戦略と日常運用
4. Pull Request とレビューの進め方
5. 競合解消、rebase、cherry-pick の実務
6. Rulesets、保護設定、権限設計
7. Merge Queue と CI の実務
8. Issue、Projects、Discussions の使い分け
9. リリース、タグ、バージョニング
10. 事故対応と復旧
11. チームに定着させる運用ルール

## 各章の要点

- 1章: Git と GitHub の役割分担を最初に明確にする
- 2章: 読みやすい履歴を残す考え方を扱う
- 3章: trunk-based と Git Flow 的運用の比較を行う
- 4章: レビューコメント、承認、責任分担を扱う
- 5章: 日常的に詰まりやすい操作を実例で整理する
- 6章: branch protection から rulesets への考え方、例外運用、権限分離を扱う
- 7章: merge queue、`merge_group`、Actions 連携、直列化されたマージ運用を扱う
- 8章: 変更管理をコード外まで広げる
- 9章: 破壊的変更、公開リリース、リリースノートを扱う
- 10章: 誤操作や壊れた履歴からの回復を扱う
- 11章: チームの合意形成と運用改善を扱う

## 他書との役割分担メモ

- `TypeScript` と `Python` に登場するコードレビューの一般論は、本書に寄せる
- `Hermes Agent` に出てくる権限制御や作業記録の一部は、本書の変更管理観点と接続する
- ただしエージェント固有の承認フローやツール設定は `Hermes Agent` 側で扱う
- GitHub の画面紹介本ではなく、破綻しないチーム運用の設計書として差別化する
