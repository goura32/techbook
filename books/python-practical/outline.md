# Outline

## 書籍の目的

- Python を業務自動化とアプリケーション開発の両面で、安全かつ保守しやすく使うための判断軸を渡す
- 文法入門で終わらず、標準ライブラリ、型ヒント、テスト、パッケージ管理、非同期、外部 API 連携まで実務に必要な範囲をつなげる

## 仮タイトル

- 技術の輪郭 Python
- サブタイトル案: 標準ライブラリ、型、テスト、3.14 時代の運用を横断して理解する

## 通しサンプル

- 題材名: `OpsBox`
- 概要:
  - 外部サービスからジョブやアラートの情報を取得し、内部モデルへ正規化する
  - 日次レポートを生成する CLI と、定期同期バッチを持つ
  - `pyproject.toml` を土台にした単一パッケージ構成で、同期処理と非同期処理の両方を扱う
- ねらい:
  - Python を「便利スクリプト」で終わらせず、運用可能なツールへ育てる流れを追えるようにする
  - 型、設定、例外、テスト、配布がどこで効くかを同じ題材で確認できるようにする
  - CLI と API 連携の間で、どこに責務を置くべきかを章ごとに見えるようにする

## 各章の要点

- 1章: Python を「便利スクリプト」ではなく「運用できる資産」として捉え直す
- 2章: Python らしい読みやすさと責務分割を扱う
- 3章: 実務で効く標準ライブラリを、使いどころと失敗例で整理する
- 4章: 型ヒントを、厳格さのためではなく API の読みやすさのために使う
- 5章: 例外、ログ、設定、CLI を運用とつながる形で扱う
- 6章: `pytest` を軸に、回帰防止と変更しやすさの接点を扱う
- 7章: `pyproject.toml` を土台に、依存関係、仮想環境、配布を一体で扱う
- 8章: `asyncio` を中心に、同期/非同期の選択と設計上の注意を扱う
- 9章: Python 3.14 の実務上重要な変化を、採用判断の視点で扱う
- 10章: API 呼び出し、認証、リトライ、レスポンス変換の責務を扱う
- 11章: 更新ルール、性能、チーム運用を含めてコードベース全体を閉じる

## 他書との役割分担メモ

- `TypeScript` とは異なり、本書は型よりも標準ライブラリ、CLI、配布、運用基盤を厚く扱う
- `Git & GitHub` にあるチームレビューやブランチ戦略の詳細は持ち込まない
- `Hermes Agent` で出てくる Python 環境構築は、必要に応じて本書か共通説明を参照する形にする
- 競合の多い入門書との差別化のため、便利スクリプトではなく「運用可能な Python」を一貫した軸にする

## 本文着手順

1. 1章で本書の判断軸を定義する
2. 2章から5章で Python の設計、標準ライブラリ、運用基盤の土台を固める
3. 6章から8章でテスト、配布、非同期を現代的なワークフローへつなげる
4. 9章で 3.14 世代の変化を取り込み、10章で外部 API 境界へ落とす
5. 11章で長期運用の原則として閉じる
