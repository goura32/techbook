# Writing Policy

## この書籍で重視すること

- Python らしい可読性
- 実務で必要な標準ライブラリ活用
- スクリプトから運用コードへ育てる視点
- 3.14 世代の変化を「新機能紹介」ではなく「採用判断」として扱う

## 本文を書く前の確認

1. `shared/style-guide.md` を確認する
2. `shared/terminology.md` を確認する
3. `shared/common-explanations.md` を確認する
4. 他書の `outline.md` と `status.md` を確認する
5. テスト、設定、パッケージ管理の一般論が重複しないか確認する
6. Python の時点依存情報は公式ドキュメントで確認する

## この書籍固有のルール

- 特定フレームワークへの依存を避け、標準ライブラリ中心に組み立てる
- サンプルコードは短く保ち、改善前と改善後の比較を多めに入れる
- 型ヒントは義務ではなく、保守性向上の道具として説明する
- パッケージ管理は `pyproject.toml` を土台にし、実務例では `uv` を主例、`pip` と `venv` を基礎として扱う
- 非同期処理は「書き方」より「どこで導入し、どこで止めるか」の判断を優先する
