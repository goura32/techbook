## はじめに

Hermes Agent は、単に「CLI から使える AI エージェント」ではありません。設定ファイル、環境変数、profiles、skills、memory、MCP、checkpoints、gateway、cron を束ねて、ひとつの運用対象として育てていくための基盤です。だからこそ、本当に重要なのは派手なデモや単発の成功体験ではありません。どこまで権限を与えるか、何を `config.yaml` へ置き、何を `.env` へ置くか、どの仕事を skill 化し、どの状態を profile で分けるか、どこで人間が止めるか。そうした地味な判断のほうが、実務ではずっと長く効きます。

本書は、Hermes Agent を話題の OSS エージェントとして紹介する本ではありません。継続利用できる開発支援基盤として理解し、安全に導入し、必要な能力だけを足し、運用が重くなりすぎる前に整理し直せるようになることを目指す本です。インストール、設定、CLI、Skills、MCP、Profiles、Memory、Checkpoints、Gateway、Cron、セキュリティまでを、ひとつの系として扱います。

本書で繰り返し使う視点は、`便利さを広げる前に、境界と責務を決める` ことです。Hermes Agent は非常に柔軟で、使い方次第では長時間運用や複数チャネル連携まで扱えます。しかし、柔軟さを無秩序に広げると、文脈が混ざり、設定が衝突し、障害時に何を疑えばよいか分からなくなります。そのため本書では、能力を増やすこと自体よりも、どの層に何を持たせるかという設計判断を優先して説明します。

その流れを具体的に追うため、本書では `ForgeFlow` という通しサンプルを使います。`ForgeFlow` は、小規模な開発チームで Hermes Agent を `coder` `triage` `ops` の 3 profile に分けて運用する想定例です。CLI から始め、Skills で手順を再利用し、MCP で能力を外へ広げ、Memory で持続させる文脈を最小限に残し、必要になってから Gateway と Cron を足していきます。つまり、「最初から何でもできる構成」ではなく、「どこまで増やすと責務が崩れるか」を確認するための題材です。

本書は、LLM や API キーの基本をすでに理解していて、Hermes Agent を安全に導入したい人、試してみたが長期運用の設計に不安がある人、設定項目や環境変数を体系的に整理したい人に向けて書いています。読み終えたときに、単なる機能一覧ではなく、「どこまで任せ、どこで観測し、どこで止め、どこで戻すか」という判断軸が手元に残ることを目標にしています。

## 本書の読み方

本書は 1章から順に読むと最も自然につながるように構成しています。特に 1章から4章は後半の土台なので、最初に通して読むのがおすすめです。そのうえで、自分の関心に合わせて後半へ進むと理解しやすくなります。

CLI 中心で使いたい読者は、1章から5章を主軸に読むと土台が固まりやすくなります。MCP や外部連携に関心が強い読者は、1章、3章、6章、10章を先に押さえるとつながりやすくなります。長時間運用やチーム導入が主目的なら、1章から4章、7章から11章を先に追うと判断軸が整います。

付録は、本文を補助する役割を明確に分けています。付録 A は `ForgeFlow` 全体像、付録 B は主要機能と責務の対応、付録 C は最小構成や安全運用の断片です。さらに、設定リファレンスは用途ごとに分けています。付録 D は `model` から `auxiliary` までの中核キー、付録 E は表示・音声・memory・skills まわり、付録 F は messaging・承認・セキュリティ・運用、付録 G は互換キーや動的キー、付録 H は認証系環境変数とプロセス単位の上書きです。本文で判断軸をつかみ、付録で具体値、既定値、関連 env、関連 CLI を引く、という使い方を想定しています。

また、本書は UI の画面遷移を追う本ではありません。Hermes Agent は更新が速く、細かな表示や導線は変わりやすいからです。本書では、CLI、設定ファイル、環境変数、権限、文脈設計、切り戻しのような、比較的古びにくい論点を優先して扱います。そのため、画面を丸暗記するよりも、章ごとの導入と結論を追いながら、自分の運用へ置き換えて読むほうが効果的です。
