## はじめに

Hermes Agent は、単なる「ローカルで動く AI エージェント」ではありません。会話、ツール、スキル、メモリ、メッセージング、Cron、MCP をひとつの運用基盤としてまとめようとしている点に、大きな特徴があります。だからこそ、導入時に見るべきなのは派手なデモだけではありません。どこまで権限を与えるか、どこに文脈を置くか、どの作業をスキルへ切り出すか、どの程度まで長時間運用を任せるか。そうした判断のほうが、実務では長く効きます。

本書は、Hermes Agent を「話題の OSS エージェント」としてではなく、「継続運用できる開発支援基盤」として理解するための本です。インストール、モデル設定、CLI ワークフロー、Skills、MCP、Profiles、Memory、Checkpoints、Cron、Gateway、セキュリティまでを、一貫した運用視点で整理します。

本書で繰り返し使う視点は、`便利さを広げる前に、境界と責務を決める` ことです。Hermes Agent は、何でもやらせようと思えばかなり広く使えます。しかし、何でも 1 つの agent へ押し込むと、文脈が混ざり、権限が広がり、誤操作時の切り戻しも難しくなります。そこで、profiles で状態を分け、Skills で手順を再利用可能にし、MCP で外部能力を明示的に足し、Checkpoints や approvals で安全域を作る、という考え方が重要になります。

その流れを具体的に追うため、本書では `ForgeFlow` という通しサンプルを使います。`ForgeFlow` は、コードレビュー、依存更新、Issue 整理、ドキュメント同期を支援する小規模な開発チーム向けの Hermes 運用例です。CLI での対話、`coder` / `ops` / `triage` の profile 分離、MCP 経由の GitHub 連携、Memory と Cron の使い分けまでを、同じ題材で見ていきます。

本書は、AI エージェントを初めて触る人のための一般入門ではありません。すでに LLM や API キーの基本を理解していて、Hermes Agent を安全に導入したい人、試してみたが長期運用の設計に不安がある人、Skills や MCP を使って自分用のワークフローを育てたい人に向けて書いています。読み終えたときに、単なる機能一覧ではなく、「どこまで任せ、どこで止め、どこで戻せるようにするか」という判断軸が手元に残ることを目指しています。

## 本書の読み方

本書は 1章から順に読むと最も自然につながるように構成しています。特に 1章から4章は、後半の Skills、MCP、Memory、Cron、セキュリティの前提になるため、最初に通して読んでおくと理解しやすくなります。

CLI 中心で使いたい読者は、1章から5章を主軸に読むと土台が固まりやすくなります。MCP や外部連携に関心が強い読者は、1章、3章、6章、10章を主軸にするとつながりやすくなります。長時間運用やチーム導入が主目的なら、1章から4章、8章から11章を先に押さえると効果的です。

付録は、本文を補助するために役割を分けています。付録 A は `ForgeFlow` の運用構成、付録 B は主要機能と責務の対応、付録 C は代表的な設定断片と安全運用断片の確認に向いています。本文で profiles や skills の位置づけを見失いそうになったときに、必要な付録へ戻る使い方が自然です。

また、本書は UI の見た目を追う本ではありません。Hermes Agent は更新が速く、見た目や細かな操作線は変わりやすいです。本書では、UI の変化に依存しにくいように、CLI、設定ファイル、権限、文脈設計、復旧可能性を優先して説明します。そのため、個別コマンドや画面を丸暗記するよりも、章ごとの導入と結論を追いながら、自分の運用へ置き換えて読むほうが効果的です。
