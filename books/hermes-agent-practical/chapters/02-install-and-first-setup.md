# 2章 インストールと最初のセットアップ

Hermes Agent の導入で最初に考えるべきことは、インストール方法そのものではありません。どのモデルを使うか、どの provider を使うか、どの profile から始めるか、どの権限を最初に開けるかです。インストールは数分で終わっても、その後の運用前提が曖昧だと、すぐに「動くが信用しにくい」状態になります。

2026年5月13日時点で公式の情報を見ると、Hermes Agent は CLI を中心に使い始める導線が明確です。ここで大切なのは、最初から Gateway や Cron まで広げないことです。導入直後は、ローカルの CLI で profile と provider の組み合わせを確認し、基本的なツール権限と作業ディレクトリの感覚をつかむだけで十分です。

最小構成としておすすめなのは、最初の profile をひとつだけ作り、読み取り寄りの仕事から始めることです。たとえば `coder` という名前でもかまいませんが、最初から「何でもする profile」にしないほうが安全です。外部リポジトリの要約、差分の確認、テスト失敗の読み取り、設定ファイルの棚卸しのように、壊れたときの影響が小さい仕事で運用感を確かめます。

モデルと provider は、精度だけで選ばないほうがうまくいきます。待ち時間、コスト、長いコンテキストへの強さ、ツール呼び出しの安定性、手元の契約条件まで含めて見ます。Hermes Agent 側の設定で差し替えやすくしておけば、あとから provider を切り替えること自体は難しくありません。難しいのは、曖昧な権限や手順を抱えたまま model だけを変えて改善しようとすることです。

最初のセットアップで特に重要なのは、作業ディレクトリとファイル変更権限の感覚です。AI エージェントの事故は、意図しない広い範囲へ触れることから始まることが多いからです。`terminal.cwd` のような基本設定を先に固定し、どこを見てよく、どこを書いてよいかを profile ごとに明示します。これは後から足すより、最初から意識したほうが楽です。

この段階では、memory も MCP も最低限でかまいません。むしろ、使わずに済むなら最初は使わないほうが全体を理解しやすくなります。導入初期に欲しいのは「能力を増やすこと」ではなく、「どの仕事なら安心して任せられるか」という感覚です。その感覚がないまま memory や外部接続を足すと、失敗時の原因が分かりにくくなります。

`ForgeFlow` でも、最初は `coder` profile だけを用意し、小さな読み取りと修正提案から始めます。そこから `triage` や `ops` を足していくことで、設定が仕事の種類にどう結びつくかが見えやすくなります。次の章では、その profile を成立させるために欠かせない、モデル、provider、ツール権限の考え方を整理します。
