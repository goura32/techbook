# 7章 Profiles、SOUL.md、Context Files

Hermes Agent を継続運用したいなら、Profiles、`SOUL.md`、Context Files の役割を早い段階で整理しておく必要があります。ここが曖昧だと、会話履歴、Skill、memory、profile の違いが混ざり始めます。その結果、「なぜ今回こう動いたのか」を説明しにくい運用になります。責務の違いは表7-1も合わせて見てください。

## 表7-1 Profiles、SOUL.md、Context Files の役割

| 要素 | 主な役割 | よくある誤解 |
| --- | --- | --- |
| Profile | 責務と権限の分離 | 人格分離そのものが安全性を作る |
| `SOUL.md` | 長く維持したい原則 | 毎回の依頼も全部書く |
| Context Files | project 固有の前提 | profile の代わりになる |

この表を先に見るだけでも、3つの層をかなり混同しにくくなります。

## 7-1. profile は人格ではなく責務分離

profile を「別人格」として紹介する説明は分かりやすい一方で、実務では誤解を招きやすいです。本書では、profile を `責務` `権限` `作業範囲` `前提` を束ねる単位として扱います。

`ForgeFlow` の3 profileを例にすると、次のように整理できます。

- `coder`
  - 変更とテスト
- `triage`
  - issue と要約
- `ops`
  - 監視と定期運用

これらは性格の違いではありません。どの仕事をし、何を見てよく、何を触ってよいかの違いです。

## 7-2. `SOUL.md` に書くべきこと

`SOUL.md` には、長く維持したい行動原則を書くのが向いています。

- 変更前に既存の制約を確認する
- 不明点があるときは断定しすぎない
- 広い修正より、小さく戻しやすい変更を優先する
- 外部投稿や大きな変更は人間へ戻す

逆に、毎回変わる作業内容や、その日だけの依頼は `SOUL.md` に向きません。そこまで詰め込むと、原則と一時指示が混ざって読みづらくなります。

## 7-3. Context Files の役割

Context Files は、`SOUL.md` より短命で、会話履歴より長持ちさせたい前提に向いています。

- プロジェクト構成
- リポジトリ固有のレビュー観点
- 依存更新時の注意点
- issue のラベル運用
- ログの読み方

これらを memory に丸投げすると、更新・削除が難しくなります。会話だけに置くと再利用できません。Context Files は、その中間を埋める層です。

## 7-4. 何を共有し、何を分けるか

運用で難しいのは、全部を共有することでも、全部を分離することでもありません。ちょうどよい線を引くことです。

共有しやすいもの:

- リポジトリ全体の一般原則
- 変更前の確認手順
- secrets を扱うときの共通ルール

分けやすいもの:

- issue の分類基準
- 通知や監視のしきい値
- profile 固有の出力形式
- 特定チャネルでの応答方針

ここを言語化しないまま profile だけ増やすと、どれを使うべきか人間のほうが迷い始めます。

## 7-5. 小さな設計例から始める

最初から `coder` `reviewer` `triage` `ops` `watcher` `release-manager` のように細かく分ける必要はありません。`ForgeFlow` では、まず `coder` と `triage` の2つでも十分に学べます。

- `coder`
  - リポジトリを読む
  - failing test を見る
  - 小さな変更を提案する
- `triage`
  - issue を読む
  - 要約する
  - 優先度候補を出す

この2つが安定してから、必要なら `ops` を足して常駐運用へ広げるほうが、責務の境界を保ちやすくなります。

## 7-6. profile を増やしすぎる失敗

Hermes Agent では、構成できること自体が魅力なので、profile を増やしすぎる失敗が起きやすいです。

- `coder` と `reviewer` がほぼ同じ権限を持つ
- `ops` と `watcher` の違いを説明できない
- 同じ Skill を複数 profile へ無秩序に配る
- Context Files が profile ごとに重複している

このとき見直すべきなのは、profile が足りないかではありません。Skill や Context Files で吸収できる違いを、profile の数で解決しようとしていないかです。

## 7-7. この章のまとめ

profile は人格分離ではなく責務分離です。`SOUL.md` は原則、Context Files は project 前提を置く場所です。読者が真似するときも、まずは2〜3個の profile で十分です。次の章では、そうして分けた profile が、何を memory に残し、何を文書へ固定すべきかを見ます。
