# 12章 OpenCode / OpenClaw との比較と使い分け

Hermes Agent を評価するとき、避けて通れないのが他の OSS エージェントとの比較です。特に OpenCode と OpenClaw は、話題性も強く、使いどころも近く見えます。ただし、この比較で大切なのは、機能の多さを並べることではありません。実務で本当に必要なのは、「自分の運用要件に対して、どの構造が一番合うか」を判断することです。

比較の軸としてまず有効なのは、日常利用の中心がどこにあるかです。CLI 中心で、profile や Skill を土台にしながら、自分の手元のワークフローを少しずつ育てたいなら、Hermes Agent はかなり相性がよいです。一方で、別のツールでは UI や特定の体験がより強いこともあります。ここで見るべきなのは「人気」ではなく、「自分が毎日触る経路」です。

次に大きいのは、状態をどう扱うかです。Profiles、Context Files、Memory Providers、Checkpoints、Cron のように、Hermes Agent は長く使う前提の構造を比較的はっきり持っています。これが強みになるのは、単発のコード補助より、役割を分けた継続運用をしたい場面です。逆に、そこまでの構造が不要なら、別のツールの軽さが合うこともあります。

OpenCode や OpenClaw を比較対象に出すとき、本書では優劣を決めることを目的にしません。なぜなら、2026年5月13日時点でもこの分野は更新が速く、機能差は短期間で変わりうるからです。だからこそ残るのは、採用判断の軸です。責務分離をどこまでしたいか、長時間運用をどこまで視野に入れるか、外部能力をどう接続したいか、停止や監査をどこまで明示したいか。ここが本質です。

`ForgeFlow` のような題材で見ると、Hermes Agent が特に向いているのは、「CLI から始めて、profile を分け、必要な能力だけを足し、あとで常駐運用へ伸ばす」という流れです。いきなり巨大な自動化を目指すより、日常の小さな手順を資産化しながら育てたい現場に合います。反対に、最初から別の体験や別のチャネル統合が前提なら、他ツールが先に候補になることもあるでしょう。

比較をするときに避けたいのは、機能表だけを見て「多いほうが良い」と判断することです。実務で重要なのは、使う機能の数ではなく、使う構造を説明できるかどうかです。どの profile が何をするのか、どこまで memory を持つのか、どこで人間が止めるのか。これを言語化しやすいなら、そのツールは自分の現場に合っています。

本書を通じて見てきた Profiles、Skills、MCP、Memory、Checkpoints、Gateway、Cron の考え方は、Hermes Agent だけでなく、他のエージェントを評価するときにも使えます。比較の結論は「Hermes Agent が常に最良」ではありません。自分の運用要件に対して、どの構造が一番説明しやすいかを選べるようになることこそ、この章の着地点です。
