## はじめに

USB は、最も身近で、最も誤解されやすい技術のひとつです。形が同じでも速度が違い、同じ USB Type-C でもできることが違い、つながるのに動かないこともあります。多くの人は USB を「コネクタ」や「転送速度の表記」として覚えますが、実務で必要なのはそれだけではありません。ホスト、デバイス、ハブ、電力、列挙、descriptor、転送方式、クラス、ドライバ、ケーブル、Power Delivery がどこでつながっているかを理解してはじめて、USB の問題は切り分けやすくなります。

本書は、USB を「仕様書の塊」としてではなく、「実装と解析のための判断材料」として読み直すための本です。USB 2.0、USB 3.2、USB Type-C、USB Power Delivery を、世代順にただ並べるのではなく、役割と層の違いが見えるように整理します。

本書で繰り返し使う視点は、`境界で切り分け、観測点を持つ` ことです。USB の不具合は、ひとつの原因に見えて実際には別の層にあります。列挙に見える問題が電力かもしれず、driver 問題に見えるものが descriptor かもしれず、速度問題に見えるものがケーブル品質かもしれません。だからこそ、host/device/power role、論理層/物理層、enumeration/transfer/class のように観点を分けて見る必要があります。

その流れを具体的に追うため、本書では `TraceDock` という通しサンプルを使います。`TraceDock` は USB Type-C 接続の小型測定デバイスで、通常は HID で制御し、bulk 転送でログを取得し、状況によっては USB PD で追加電力を受ける構成です。実装例として完成品を見せることよりも、どの仕様がどこへ効くかを同じ題材で追うことを目的にしています。

本書は、USB 製品の買い方や marketing 名称を覚えるための本ではありません。USB を使う製品を実装、解析、保守したい開発者、USB 規格書を読み始めたがどこから押さえるべきか迷っている人、Type-C と PD を含めた全体像を整理したい人に向けて書いています。読み終えたときに、転送速度の暗記ではなく、「どこを見れば問題が切り分けられるか」という判断軸が残ることを目指しています。

## 本書の読み方

本書は 1章から順に読むと最も自然につながるように構成しています。特に 1章から4章は、後半の Type-C、PD、device class、解析の前提になるため、最初に通して読んでおくと理解しやすくなります。

まず USB の土台を固めたい読者は、1章から4章を主軸に読むと全体が見えやすくなります。Type-C や電力に関心が強い読者は 5章から7章を重点的に見るとつながりやすくなります。実装や解析が主目的なら 3章、4章、8章、9章、10章を主軸にするのが自然です。

付録は、本文を補助するために役割を分けています。付録 A は `TraceDock` の全体構成、付録 B は descriptor と class の対応、付録 C は capture、dump、debug の代表断片を確認するためのものです。本文で `TraceDock` 全体像や descriptor の位置づけを見失いそうになったときに、必要な付録へ戻る使い方が自然です。

また、本書は USB-IF の仕様や文書を土台にしていますが、仕様の全文を要約する本ではありません。実装や解析で先に押さえるべき観点へ絞り、どの改訂が何に効くかを見えるようにしています。そのため、条文の順番を追うより、章ごとの導入と結論を追いながら自分の環境へ置き換えて読むほうが効果的です。
