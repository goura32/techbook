# 10章 USB4、Thunderbolt 互換、DisplayPort Alt Mode

現代の USB Type-C で読者の関心が強いのは、`USB4` `Thunderbolt` `映像出力` の関係です。ここは marketing 上も混線しやすいので、規格の境界を明確にしておく価値があります。

## 10-1. USB4 は何を追加するか

本書で USB4 を扱う目的は、全仕様を深掘りすることではありません。`Type-C の上で、より高速な transport と複数プロトコルの共存がどう整理されるか` を理解することです。USB4 は USB 2.0 や USB 3.2 の土台を消すのではなく、その上に新しい発見手順や transport を追加します。

## 10-2. discovery と entry

USB4 では、いきなり最終モードへ入るのではなく、何が対応しているかを相手と見ながら進みます。ここで cable、device、hub、dock の能力差が効いてきます。つまり、USB4 の問題は `USB4 があるかないか` の二択ではなく、`どこまで discovery でき、どこへ entry できるか` の問題として見るほうが現実的です。

この見方が重要なのは、ユーザーの体験が `USB4 対応なのに思ったとおり動かない` になりやすいからです。実際には `host は対応` `dock も対応` `ただし cable が必要条件を満たさない` `または display / storage / power の組み合わせで entry 条件が変わる` といったことが起きます。だから USB4 を debug するときは、製品ラベルではなく、経路上の各要素が何を広告しているかを追う必要があります。

## 10-3. Thunderbolt 3 compatibility

現代の読者が気になるのは、USB4 と Thunderbolt がどう重なるかです。本書では、Thunderbolt 3 compatibility を `USB4 文脈の互換論点` として扱います。別規格の全体像を説明するのではなく、`なぜ同じ Type-C でも dock や cable で結果が違うのか` を理解するための材料に絞ります。

ここで重要なのは、`Thunderbolt 対応` の一言を万能の上位互換と見ないことです。読者が現場で知りたいのは、`どの host とどの dock とどの cable の組み合わせで、何が有効になり、何が無効になるか` です。Thunderbolt 互換はその判断材料のひとつであって、USB4 の一般論だけでも、Thunderbolt の一般論だけでも片付きません。

## 10-4. DisplayPort Alt Mode で映像が出る仕組み

映像出力は USB のデータ転送とは別軸です。DisplayPort Alt Mode では、Type-C 上の lane を映像へ振り分けることでディスプレイ出力を行います。ここで大切なのは、`USB-C だから映像が出る` のではなく、`DisplayPort Alt Mode が成立しているから映像が出る` という理解です。

この違いが分かると、`給電はある` `USB device としては見える` `でもディスプレイだけ映らない` という症状を、単純な接触不良や OS 設定だけで片付けにくくなります。映像出力は data lane の使い方や相手側の mode support に依存するため、USB の中でも別の切り分け筋を持ちます。

さらに実務では、映像 lane を厚く使う構成と USB data を厚く使う構成の間で、同時成立できる条件が変わります。`映像は 4K で出るが USB 側は高速でない` `映像は出るが想定した周辺機器が一部しか動かない` という症状は、OS の不具合より lane 配分や dock 内部構成を疑うべきことが多いです。DisplayPort Alt Mode は映像機能そのものだけでなく、同時利用条件を含めて理解したほうが役立ちます。

## 10-5. USB、映像、電力が競合する場面

同じ Type-C で data、video、power を同時に扱うと、lane 配分や power 条件が絡みます。だから `USB データは遅くなるが映像は出る` `給電はされるが期待した映像モードへ入らない` `dock によって結果が変わる` といった現象が起きます。これを USB の単独問題として見ると、かなり誤解しやすくなります。

読者が最初に知りたいのは、`全部同時に最大性能では使えないことがある` という事実です。たとえば映像帯域を優先すれば USB data 側の条件が変わることがありますし、power 条件が足りなければ dock 全体の挙動も変わりえます。ここは marketing の表現より、lane と power と相手機能の三者関係として見るほうが実務的です。

## 10-6. dock、hub、cable で結果が変わる理由

Type-C ドックやハブは、単なる延長ではありません。内部で mux、retimer、PD 制御、Alt Mode 切替、USB hub 機能が重なっていることがあります。だから同じ PC と同じディスプレイでも、dock を変えると結果が変わります。ここで必要なのは万能の結論ではなく、`どの層が変わったか` を意識して切り分けることです。

切り分けでは、`直結ではどうか` `別 cable ではどうか` `給電あり / なしでどうか` `USB storage や input device を同時接続するとどう変わるか` といった比較が効きます。映像と USB と電力が同じ物理口へ集まるからこそ、症状の見え方も単独仕様の本より複雑になります。この章の役割は、その複雑さを仕様の境界へ戻して考えられるようにすることです。

## 10-7. この章のまとめ

USB4、Thunderbolt 互換、DisplayPort Alt Mode は、いずれも Type-C 文脈で読者の関心が強い論点です。ただし、それぞれは別仕様です。次の章では、これらを実際にどう観測し、どこから試験やコンプライアンスへつなぐかを整理します。
