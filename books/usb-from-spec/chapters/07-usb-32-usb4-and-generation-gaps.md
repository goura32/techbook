# 7章 USB 3.2、USB4、その前後関係

USB の世代名は、多くの開発者を混乱させてきました。USB 2.0、USB 3.0、USB 3.1、USB 3.2、USB4。しかも marketing 上の表現と規格名が一致しないこともあります。だから本書では、世代名を暗記するより、「どの層に何が足されたのか」を見るほうを優先します。

USB 2.0 は、いまでも列挙、control transfer、device class の土台として重要です。USB 3.2 はそこへ高速側の経路を重ねますが、USB 2.0 的な世界が消えるわけではありません。だから device を作るときも debug するときも、「USB 3.x だから USB 2.0 の知識はいらない」とはなりません。

ここで実務的に重要なのは、「何が足され、何がそのまま残るか」を分けて見ることです。高速化されたからといって、enumeration の基本や class の契約が消えるわけではありません。むしろ高速側の問題が加わるぶん、土台の USB 2.0 的な理解がないと、何が新しい問題で何が昔からの問題かが見えにくくなります。

USB-IF の公開情報では、USB 3.2 は独自の技術ページと interop 情報を持ち、文書ライブラリには USB4 Specification v2.0 も掲載されています。ここから分かるのは、現代の USB はひとつの一本線ではなく、複数の世代と関連仕様が重なっているということです。

この「重なっている」という感覚はとても大事です。実際の製品では、marketing 上は USB 3.2 や USB4 をうたっていても、field での不具合は USB 2.0 的な enumeration や class の問題だった、ということが普通に起きます。逆に、USB 2.0 では安定していたものが高速側の path でだけ不安定になることもあります。世代が増えるというのは、古い論点が消えることではなく、観測点が増えることです。

ここで特に気をつけたいのは、Type-C と USB 3.2/USB4 を同一視しないことです。Type-C は connector ecosystem の話であり、USB 3.2 や USB4 は主に性能やプロトコルの話です。Type-C だから USB4 とは限りませんし、Type-C でも USB 2.0 しか通らない構成はありえます。この切り分けができるだけで、かなり多くの誤解を避けられます。

backwards compatibility も、言葉ほど単純ではありません。つながることと、期待した速度や機能で動くことは別です。USB の世代差分を考えるときは、「最低限どこへフォールバックするか」「どのケーブルや host controller でどの経路が使われるか」を見る必要があります。

この観点で見ると、support 文書や製品仕様にも書き方の差が出ます。よい仕様は「最大速度」だけでなく、「最低限どの mode で動くか」「どの cable 条件でその機能が有効か」を示します。悪い仕様は USB 3.2 や USB4 という名前だけを出して、現実の動作条件を隠します。本書が marketing 名より layer を優先するのは、この差が field で効くからです。

本書では USB4 を深掘りしませんが、存在を無視もしません。理由はシンプルで、現代の Type-C 製品では USB4 の影響を完全に切り離せないからです。ただし、USB を学ぶ入り口としては、まず USB 2.0、USB 3.2、Type-C、PD の関係を整理するほうがはるかに重要です。

学習順としても、いきなり USB4 から入るより、まず「USB 2.0 の列挙と class」「USB 3.2 の高速 path」「Type-C と PD の別軸」を整理したほうが、あとで USB4 を読むときの理解が安定します。全部を同時に理解しようとすると、かえって何も区別できなくなります。

次の章では、物理層や世代差分の話から少し戻って、host 側で実際に device がどう見えるかという観点で、device class、driver、OS の違いを整理します。
