# 1章 USB を仕様から理解するための見取り図

USB はあまりにも身近なため、技術としてではなく記号として消費されやすい領域です。USB-A、USB-C、5Gbps、20Gbps、給電、映像出力。そうした言葉は広く知られていますが、それらが何を意味し、どこまでを意味しないのかは意外と曖昧です。実務で困るのはこの曖昧さです。つながるのに動かない、Type-C なのに期待した速度が出ない、給電はされるのに認識しない。こうした問題は、USB を形と名称だけで理解していると切り分けづらくなります。

本書で USB を扱うときの中心的な視点は、`境界で切り分け、観測点を持つ` ことです。USB の問題は、見えている現象と原因の層がずれていることが多いからです。認識しない問題に見えて、実は電力交渉かもしれない。速度問題に見えて、ケーブル能力かもしれない。driver 問題に見えて、descriptor の構成ミスかもしれない。だからこそ、connector、power、enumeration、transfer、class、driver を別々に見られることが重要になります。

本書は、USB 2.0、USB 3.2、USB Type-C、USB Power Delivery を、実装と解析の観点でつなぎます。規格書の全文要約ではなく、どこを読むと実装判断やデバッグ判断へつながるかを優先します。USB4 も無視はしませんが、本書の主軸は USB を理解するための土台に置きます。

ここで大切なのは、USB をひとつの仕様としてではなく、複数の層が重なった体系として見ることです。少なくとも、次の 5 層を分けて見られるようになると理解が進みやすくなります。

- 物理的な接続:
  - connector、cable、signal path
- 電力:
  - default power、power role、PD contract
- 列挙:
  - attach、reset、descriptor、configuration
- 機能提供:
  - transfer type、device class、endpoint
- host 側の受け取り:
  - driver、OS、user-space API

商用製品で USB が難しいのは、障害報告がこの 5 層を混ぜて届くからです。ユーザーは「つながらない」と言いますが、実際には「給電はされているが class が見えない」「列挙はするが logging が取れない」「高負荷時だけ PD が落ちる」といった別々の現象かもしれません。だからこそ、本書では最初から層を分けて扱います。

その流れを具体的に追うため、本書では `TraceDock` という通しサンプルを使います。`TraceDock` は USB Type-C 接続の小型測定デバイスで、HID による制御、bulk 転送によるログ取得、条件付きの USB PD 利用を持ちます。ここで大切なのは、完成品の設計例として見ることではなく、どの仕様がどこへ効くかを同じ題材で追うことです。

USB を仕様から理解する価値は、実装者だけのものではありません。host 側のソフトウェアを書く人にとっても、どの interface が見えるのか、なぜ OS によって挙動が違うのか、どの転送方式を選ぶべきかを判断する助けになります。逆に firmware や hardware 側の人にとっても、host が何を期待し、どこで誤解しやすいかを知ることで、構成をかなり整理しやすくなります。

特に host 側の人にとって USB の理解が重要なのは、device を API のように扱いすぎないためです。USB device は、OS や driver を挟んで見えるため、外からは単純な入出力口のように見えます。しかし実際には、その手前で descriptor、class、endpoint、power 条件が効いています。つまり host 側ソフトウェアが不安定なとき、その原因が必ずしも host 側にあるとは限りません。反対に、device 側の人も host の見え方を理解していないと、現場でのサポートが難しくなります。

ここで大切なのは、USB を「全部知る」ことを目標にしないことです。USB の関連仕様は広く、細かい改訂も続きます。必要なのは、いま見るべき範囲を切り出し、その範囲の中で何が host/device の契約なのかを掴むことです。規格書を読むというのは、全部を覚えることではなく、判断に必要な場所へ戻れるようになることです。

本書の読み方としては、まず 1章から4章で USB 2.0 的な土台を作り、そのうえで Type-C と PD を別軸として追加し、最後に class、実装、解析、保守へ戻るのが自然です。こうすると、Type-C や USB4 の新しさに引っ張られず、どの層が本当に問題なのかを見失いにくくなります。

`TraceDock` の全体構成を先に見返したいときは付録 A が役に立ちます。次の章では、USB の最初の土台として、host、hub、device、endpoint といった役割を整理し、どの単位で USB を捉えるべきかを見ていきます。
