# 1章 USB を規格として読むための見取り図

USB は、最も身近で、最も誤解されやすい技術のひとつです。コネクタの形、速度表記、給電、映像出力、ゲームコントローラー、ドック、充電器。日常ではひとつの名前で呼ばれていても、規格上は別の層の話が重なっています。本書の出発点は、この重なりを分けて理解することです。

## 1-1. USB をコネクタ名で理解しない

USB-C という言葉だけでは、速度も、電力も、映像も決まりません。USB Type-C は主にコネクタと接続の仕組みの話であり、USB 2.0、USB 3.2、USB4、DisplayPort Alt Mode、USB Power Delivery は別の層にあります。ここを最初に分けないと、読者が最も知りたい「なぜ同じ USB-C なのに結果が違うのか」を説明できません。

## 1-2. 本書で分けて扱う層

本書では、USB を少なくとも次の 6 層に分けて扱います。

- 物理接続: connector、cable、signal path
- 電力: default power、power role、PD contract
- 列挙: attach、reset、descriptor、configuration
- 転送: control、bulk、interrupt、isochronous
- 機能公開: class、interface、endpoint、driver binding
- 拡張: USB4、Thunderbolt 互換、Alt Mode

この区切りがあると、`つながるのに映像が出ない`、`給電はされるのに高機能モードへ入らない`、`OS ごとに controller の見え方が違う` といった現象を、別の問題として切り分けやすくなります。

## 1-3. 規格、観測、ハード前提

本書の中心は、`規格` `観測` `最低限のハード前提` の 3 本柱です。規格の説明だけでは、現場で何を見るべきかが残りません。観測手法だけでは、なぜそのログをそう読むのかが分かりません。ハード配線だけでは、OS や driver がどう見ているかへつながりません。この 3 本を一冊でつなぐのが本書の役目です。

## 1-4. 本書の対象範囲

本書は USB 全部の辞典ではありません。中心に置くのは、`USB 2.0` `USB 3.2` `USB Type-C` `USB Power Delivery` `USB4` と、それらを扱うための観測手法です。Thunderbolt 互換や DisplayPort Alt Mode も扱いますが、専用専門書の深さまで掘るのではなく、現代の USB Type-C を理解するために必要な範囲へ絞ります。

## 1-5. どの一次情報を土台にするか

規格の骨格は USB-IF の仕様書と技術ページを土台にします。Type-C の映像出力は VESA の情報も参照します。観測手法は Linux の `usbmon` 文書と Wireshark の公式情報を基準にします。つまり本書は、二次解説を寄せ集めるのではなく、一次情報を読む入口として設計しています。

## 1-6. 本書の読み方

まず土台から入りたい読者は、1章から5章を通すのが自然です。Type-C、PD、USB4、映像出力に関心が強いなら 8章から10章を厚く読むとつながりやすくなります。実装や解析が主目的なら、3章、4章、9章、11章、12章が中核になります。

この章の結論は単純です。USB をひとつの名前でまとめて理解しないことです。何が connector の話で、何が列挙の話で、何が電力の話で、何が拡張の話かを分けるだけで、USB はかなり読みやすくなります。次の章では、その土台として USB 2.0 の基本モデルを整理します。
