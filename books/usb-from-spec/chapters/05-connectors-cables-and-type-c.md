# 5章 コネクタ、ケーブル、USB Type-C

USB Type-C が広く普及したことで、USB は分かりやすくなったように見えて、実際には混乱も増えました。どちら向きでも挿せる、同じ形で多くの機能を載せられる、細くて扱いやすい。そうした利点がある一方で、「同じ形なら同じ能力」という誤解も生まれやすくなっています。

まず押さえたいのは、Type-C は形状と信号体系の一部であって、それだけで速度や電力や alternate mode を保証しないということです。Type-C であっても USB 2.0 だけの製品はありえますし、高電力が使えるとも限りません。逆に、Type-C は cable capability や role signaling を含めて、従来よりも多くの前提を運ぶ入り口にもなっています。

ここで混乱しやすいのは、「Type-C にした」という意思決定が、実際には複数の論点を束ねていることです。小型化したい、上下を気にせず挿したい、将来的に高電力へ伸ばしたい、別の mode にも対応できるようにしたい。これらは同じ Type-C という言葉で語られますが、設計上は別々の話です。どの理由で Type-C を選んだのかが曖昧なままだと、要件も debug もぶれやすくなります。

legacy connector の時代は、見た目からある程度の役割を推測しやすい面がありました。Standard-A は host 側、Standard-B は device 側、といった感覚です。Type-C ではそれが崩れます。だからこそ、見た目ではなく power role、data role、cable capability を分けて理解する必要があります。

実務で特に困るのは、「同じ Type-C ケーブルで、ある host では動き、別の host では不安定」という現象です。ここで software 側から見ると driver 問題に見えることがありますが、実際には cable capability、port 実装、給電条件、signal margin が絡んでいることがあります。Type-C は便利な形状であると同時に、観測すべき条件を増やした規格でもあります。

ケーブルも重要です。USB の不具合は device や host の実装問題に見えて、実際には cable quality や cable capability の問題であることが少なくありません。Type-C では特に、同じ形の cable でも対応する速度や電力が違います。物理層の問題を論理層のせいにしないためには、ケーブルを仕様の一部として見る必要があります。

USB の実務では、少なくとも次の観点で cable を記録しておくと、再現性が上がります。

- passive か active か
- USB 2.0 だけか、SuperSpeed 系も通るか
- 給電能力がどこまであるか
- 長さと取り回し
- host 直結か hub 経由か

「Type-C ケーブルを使った」という記録だけでは、ほとんど何も言っていないのに近い、という感覚を持ったほうが安全です。

また、Type-C の話をするときに alternate mode や映像出力の話が強く見えますが、本書ではそこを中心にしません。ここで重要なのは、USB とそれ以外の機能が同じ口から出ることで、観測点が増えているということです。つまり「映像が出ない」問題と「USB device が列挙しない」問題は、同じ Type-C でも切り分けるべき層が違います。

この章で押さえたいのは、Type-C を「万能で新しいコネクタ」として崇めないことです。Type-C を採用しても、最初に決めるべきなのは従来と同じく、device として何を提供するか、どこまでの power condition を前提にするか、どの cable 条件をサポート範囲にするかです。見た目の統一は、設計判断を消してはくれません。

`TraceDock` でも Type-C を採用していますが、それは万能性のためではありません。小型で扱いやすく、将来的に電力交渉を伸ばしやすいからです。ここで学びたいのは、Type-C を採用したからといって、最初から全部の機能を背負う必要はないということです。次の章では、その Type-C と強く結びつく USB Power Delivery を扱い、電力とデータの話をはっきり分けます。

`TraceDock` では、最初の設計判断として次の線を引きます。

- Type-C は採用する
- USB 2.0 的な基本列挙だけでも成立させる
- cable の違いで壊れない最小機能を持つ
- 高負荷機能だけを PD 条件へ寄せる

この順番を守ると、Type-C 採用がそのまま複雑さの爆発につながりにくくなります。逆に、Type-C 採用と同時に高速化、高電力化、複数 mode 対応を全部始めると、原因の層が急に見えにくくなります。次の章では、その Type-C と強く結びつく USB Power Delivery を扱い、電力とデータの話をはっきり分けます。
